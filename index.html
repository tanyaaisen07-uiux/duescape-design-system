Duescape system reference

The working specification for Duescape, a subscription tracker that tells people what to cancel rather than only what they pay. Every value on this page is taken from the Figma variables, so the file and this page cannot drift apart.

Typeface Plus Jakarta Sans Brand #0057FF Artboard 393 × 852 Themes Light · Dark Contrast WCAG AA Components 36

Two collections, two layers. Duescape/Primitives holds 58 raw values in a single mode. Duescape/Semantic holds 28 tokens in Light and Dark modes, each one an alias to a primitive. Product surfaces reference the semantic layer only, which is why switching a frame’s mode retints an entire screen.
Changed in this revision. Navigation is five labelled tabs with no central action. Cancelling is a destructive button with a confirmation, never a toggle. Green is reserved for status and no longer doubles as a brand accent. Status badges carry a glyph as well as a tone. Currency is €12,99 with a comma. The type ramp lost its near-duplicate steps and the status text tones were darkened to pass AA.

Icons & navigation

31 line icons on a 24px grid, 1,6px stroke, rounded caps and joins. Stroke inherits currentColor, so an icon takes the tone of whatever it sits in.

Accessibility

Measured contrast for every text pairing the product uses. Six of these failed in the first draft and were fixed in the tokens rather than in the layouts, so the correction reached every screen at once.

PairingThemeRatioAA
Colour is never the only signal. Status badges carry a glyph, the current tab carries weight as well as tone, and chart identity comes from labels rather than hue. Touch targets are 44 × 44 minimum, including the 20px checkbox, which sits inside a 64px row. Disabled controls are exempt from the contrast minimum by the specification and are the only pairings below 4,5:1.

Contribution

How the library grows without fragmenting. Anyone can propose a component; the system keeps one owner for naming, tokens and the final call.

1 · CheckAny designerSearch the library first. Most requests are a missing variant of something that already exists.Existing component ruled out
2 · ProposeAny designerOne-page request: the use case, screens where it appears, and why current components do not cover it.Request logged
3 · TriageSystem ownerWeekly decision: reuse as is, extend with a variant, keep local to the product, or build as new.Decision recorded with a reason
4 · BuildProposer + owner + engineerFigma component on semantic variables only, all states, contrast check, spec for code.Design and code match
5 · ReleaseSystem ownerChangelog entry, version bump, note on what changed for teams already using it.Published to the library
Local first. A one-off pattern lives in the product file. It moves into the system when a second screen or team needs it. Extend before adding. A new variant beats a new component; a new component beats a detached copy.

AI-readable system

The same rules have to work for a person reading this page and for an assistant generating a screen. So every decision exists in two forms: visual here, structured in tokens.json.

Structured tokens

W3C Design Tokens format. Semantic tokens alias primitives, light and dark share one set of names, every token carries its role as a description.

color · semantic.light · semantic.dark · typography · spacing · radius · motion · rules

Names that explain themselves

category/role-state, for example action/primary-hover. A name says where a token is used, never what it looks like, so a model can pick the right one without seeing the palette.

Rules as sentences

Usage rules ship inside the token file as plain sentences: no raw hex on screens, green only for status, destructive actions need a confirmation. A generated layout can be checked against them line by line.

Where AI output gets overridden. Anything around money and destructive actions is reviewed by hand: amount formatting, cancel flows, error copy. Generated screens that use a primitive or a hex value are rejected before review, because they break theming silently.

Developer tokens

Drop-in custom properties. Application code references the semantic block; the primitive block exists so the semantic block has something to point at. The same values are available as structured JSON in tokens.json.
